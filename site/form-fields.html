Form fields

The PiperX field request (FieldRequest): what the messenger shows when the agent asks for a name, email, phone number, picklist and so on. It's markup only, with no Piper and nothing behind the buttons. Each state is captured from fireball by rendering the real component with its store in that state. Each one sits in its own open shadow root with the widget's stylesheet, as on a customer's page. In sidebar and docked, picklists render in the chat timeline under the agent's question, so those are captured there. Piper colors the fields with the team's theme: the Theme options set the same --q-* properties on each host that applyThemeCssVars does. Each frame is its own viewport. Open one on its own to use DevTools on it.

What to check

  • Errors read as errors: the full-name, invalid email, business email, phone and failed-submit states show red text under the field, and the submit arrow is disabled for every invalid value.
  • Placeholders and values: an empty field shows its placeholder (the admin's own on “Short answer, custom placeholder”); a filled one shows the value in the same type.
  • Picked chips stand out: the two picked multi-picklist chips look selected and a Continue button appears. A single picklist has no picked state: a click submits at once.
  • Stacked picklists: stacked chips sit one per row; full width stretches each to the field’s width.
  • Collapsed shows the question: in Collapsed right, the agent’s question sits above the field on the white card.
  • Narrow widths: at 320, long chip labels and the long answer wrap instead of overflowing.

Refresh the capture after fireball changes: npm run form-fields:refresh. See the README.
